状态图用于刻画一个单一业务对象在其生命周期内，由于接收外部事件（Event）而发生的状态变迁（State Transition）。

### 1. 状态图核心元素含义说明

*   **初态（Initial State）**：用**黑色实心圆点**表示，代表状态机生命周期的起点，一个状态图只能有一个初态。
*   **终态（Final State）**：用**双圆环（同心圆内带实心圆点）**表示，代表对象生命周期的终结，可以有多个终态或没有终态。
*   **状态（State）**：用**圆角矩形**表示，写有该状态的名称（通常为英文大写）。代表对象在生命周期中某一时间段所处的一种稳定物理或逻辑状态。
*   **状态迁移线（Transition）**：**带箭头的实线**。代表状态发生改变的路径。
    *   **标符格式**：`事件 [守卫条件] / 动作`（Event [Guard] / Action）。
    *   **事件**：触发迁移的外部输入（如“提交审核”）。
    *   **守卫条件**：布尔表达式，只有条件为真时迁移才会被触发（如 `[信用分 > 700]`）。
    *   **动作**：迁移发生时系统执行的瞬时行为，执行完后立即进入新状态。

### 2. 实战例图

#### 2.1 交易执行状态图（TransactionStatus）

*   **题目背景**：设计一个银行ATM取款交易处理的生命周期状态图。交易创建后，进入处理中状态，处理成功则交易成功，若余额不足或超时则交易失败，交易失败后允许用户发起重试。

stateDiagram-v2
    [*] --> CREATED : 提交请求 / 创建交易
    CREATED --> PROCESSING : 开始调度 / 发送网关指令
    PROCESSING --> SUCCESS : 确认出钞 [扣款成功] / 完成交易
    PROCESSING --> FAILED : 调度失败 [余额不足 或 超时] / 登记失败记录
    FAILED --> CREATED : 重试取款 / 重设交易
    SUCCESS --> [*]
    FAILED --> [*]
`} />

#### 2.2 信用卡申请与卡片生命周期状态图（CardApplicationStatus）

*   **题目背景**：设计一个银行信用卡申请审批与挂失的生命周期状态图。用户提交申请资料后，进入后台审批，通过后变为审批通过（已发卡）状态，拒绝后允许重新提交，已发卡后支持申请销户/挂失操作。
